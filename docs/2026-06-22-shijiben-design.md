## 一、产品定位

### 是什么
一个纯粹的本地时间记录工具。受《奇特的一生》启发，核心理念是：**单纯地记录生活，不设 TODO、不强迫复盘，让记录本身成为习惯。** 通过长期记录，自然看见时间和精力花在哪里，不对自己评判，减少内耗。

### 不是什么
- 不是日历应用、不是 TODO 应用、不是复盘应用
- 不是计划清单、不是时间管理、不是任务管理、不是打卡应用
- 不联网、无社区、无提醒推送

### 核心哲学
1. **记录即审视**：未经审视的人生不值得一过。记录是审视的前提。如果每做两件事之间都要犹豫、墨迹、准备很久，就会形成空白。目的是减少空白。
2. **App 反映现实，不评判现实**：事情没做就是没做，这个事实应该可见。预写的事件如果没做，顺延到明天——不是 nagging，是诚实。不让一件事彻底消失在意识之外。
3. **轻量存在**：时间可视化静静在那，不制造焦虑。打开 App 感受到的是平静和掌控感，不是压力。

## 二、技术架构

### 技术选型
- **框架**：Flutter（Android 优先，未来可扩 iOS/桌面）
- **本地存储**：SQLite + drift（类型安全、响应式查询）
- **状态管理**：Riverpod
- **路由**：go_router
- **开发预览**：支持 `flutter run -d chrome` 在浏览器中热重载迭代，日常 UI 开发无需启动模拟器

### 项目结构
```
shijiben/
  docs/            # 文档：设计 spec、需求记录
  design/          # 设计思考、HTML 原型/mockup
  lib/
    core/          # 主题、8-bit 调色板、共享组件
    data/          # drift 数据库、表定义、DAO
    features/
      timeline/    # 时间轴主视图
      recording/   # 三种记录方式
      tags/        # 标签管理
      heatmap/     # 热力图（v2）
      time_viz/    # 时间可视化（v2）
    main.dart
```

### 设计原则
- 数据模型简单，不过度抽象。Event 和 Note 是独立表，不强行合并。
- 8-bit 美学集中在 `core/theme`，不散落各处。
- 本地优先：所有数据在设备上，不依赖任何网络。

## 三、数据模型

| 字段 | 类型 | 说明 |

| 字段 | 类型 | 说明 |

### 事件状态流转
```
预写 ──→ not_started
              │
      开始计时/手动标记
              │
              ▼
         in_progress（end_time = null）
              │
          停止计时
              │
              ▼
          completed（填入 end_time）
```

**自动顺延机制**：
- App 打开时检查，把之前日期的 `not_started` 事件移到今天（start_time 改为次日相同时刻）
- 不做后台定时（符合本地、不联网原则）
- 目的：不让预写的事情彻底消失在意识之外

## 四、核心 UI：时间轴

### 布局
- **纵向滚动**，一天一个 section，顶部日期头
- **Y 轴 = 时间**：固定比例（1 小时 = 固定像素高度），整点有刻度线
- **事件块**：按 tag 颜色填充，高度 = 时长，左侧贴时间轴
- **随笔点**：时间轴右侧的小圆点，点开展开文字
- **当前时间指示线**：一条横线标示"现在"
- **向上滑**：自然回到昨天、前天……

### 实时计时展示（两者结合）
1. **顶部状态条**：显示"正在：xxx 已 23min"，点击可停止
2. **时间轴上实时增长**：进行中的事件块从开始时间延伸到当前时间线，实时刷新

### 8-bit 美学
- **色板**：柔和复古色板（有限色板，饱和度适中，兼顾 8-bit 感和阅读舒适）
- **组件**：像素边框、复古字体
- **集中管理**：`core/theme` 中定义色板常量、像素边框组件、字体配置

## 五、记录流程

三种入口都从时间轴的 FAB（悬浮按钮）进入：

### 1. 实时计时
点 FAB → "开始" → 填标题 + 选标签 → 计时中（顶部状态条 + 时间轴实时增长）→ 点停止 → `completed`

### 2. 事后补录
长按时间轴空白处 → 在该时间点新建事件 → 填标题/时间范围/标签 → 直接 `completed`

### 3. 提前写
同补录流程，但时间选未来 → `not_started` 状态。它已经是事件，不是待办。如果当天未开始，自动顺延到次日。

## 六、标签系统

- **首次打开**：空标签起步，用户自行创建
- **标签管理**：用户可增删改标签，为每个标签选择 8-bit 色板中的颜色
- **作用**：分类与着色。在时间轴上通过颜色一眼区分事件类型
- **不做**：不做时长汇总统计（v1），不做层级标签

## 七、回看与可视化（V2）

### GitHub 式热力图
- 每一天是一个方块
- **填充 = 记录的时间覆盖比例**：没有记录 = 空白方块；记录了一半时间 = 面积填一半
- 价值：照见"空白"。未记录的时间 = 未审视的时间 = 可能的犹豫和墨迹
- 目的：减少空白，告诉自己"我知道我在做什么，你看，都记录了"

### 时间可视化（轻量存在）
- **今天剩余时间**：打开 App 时静静可见（如"今天还剩 6h 23m"）
- **今年/一生剩余时间**：在单独页面，想看才看
- 不制造焦虑，只是提醒时间在流逝

### 随笔功能（V2 完整化）
- V1 仅支持时间轴右侧点的展示
- V2 补充：随笔的创建入口、列表查看、编辑删除
