# Direction Report — Cycle 13

> 基于 `/better direction` 生成。本报告为产品方向建议，非可执行计划。
> 用户决定是否采纳；若采纳，可用 `/better <category>`（如 ux / ui / tests）落地。

## 产品哲学锚点

来自 `MY_ORIGIN_GOAL.md` + `docs/2026-06-22-shijiben-design.md`：

1. **记录即审视**：未经审视的人生不值得一过，记录是审视的前提
2. **App 反映现实，不评判现实**：事情没做就是没做，事实应可见
3. **轻量存在**：不制造焦虑，打开 app 感受到平静和掌控感
4. **不是什么**：不是 TODO / 不是日历 / 不是打卡 / 不是计划清单 / 不是复盘应用
5. **原始核心诉求**（MY_ORIGIN_GOAL.md）："当我想回顾一周自己的生活时，我可以快速的查看自己做了什么，花了多少时间"

## 现状盘点

V1/V2/V3 核心功能已全部落地：时间轴、记录弹窗、自动顺延、随笔、热力图（月+年）、时间可视化（今天/今年/一生）、搜索、数据导出/导入、设置页、调试控制台。

回看粒度现状：**日**（时间轴）→ **月**（热力图月视图）→ **年**（热力图年视图）。缺少**周**这个中间粒度。

## 方向建议（按优先级）

### 方向 1：周视图回看（最高优先级）

**为什么**：用户原始诉求明确提到"回顾一周自己的生活"，但当前回看粒度从日跳到月，缺少周这个最贴合原始诉求的中间层。月视图颗粒度太粗（30 个方块），日视图只看当天，周视图正好对应"回顾一周"的自然时间感知。

**是什么**：
- 热力图页新增"周"tab（或月视图内可缩放到周）
- 周视图：7 个方块（周一到周日），每个方块显示该日记录覆盖比例（复用现有热力图色阶逻辑）
- 方块点击 → 跳转到该日时间轴（复用现有 heatmap_target_date 跨屏传值机制）
- 顶部显示本周总记录时长 + 覆盖率（事实展示，不评分）

**不是什么**：
- 不是周报推送（不打扰、不强迫复盘）
- 不是 streak 打卡（不显示连续记录天数，避免制造焦虑）
- 不是周计划（不是 TODO）

**符合哲学**：呼应原始诉求"回顾一周"，轻量可选（用户主动进入才看），只展示事实不评判。

**预估工作量**：中（复用热力图色阶 + 跨屏传值，新增 WeekGrid 组件 + 周聚合计算）

### 方向 2：时间去向聚合（按标题看时间分配）

**为什么**：用户说"能感受到自己的进步，把时间花在正确的事情上"——当前只有覆盖率，缺少"时间花在哪"的视角。但需谨慎避免滑向"评判"。

**是什么**：
- 新增页面或设置页子项：按事件标题聚合显示总时长（如"阅读 12h / 运动 3h / 工作 40h"）
- 时间范围可选：本周 / 本月 / 本年 / 全部
- 纯展示，不评分、不对比目标、不显示百分比排名

**不是什么**：
- 不是时间管理报表（不评分、不设目标）
- 不是效率分析（只展示事实）
- 不暗示"应该"花更多时间在某类事上

**符合哲学**：记录即审视——看见时间去向是审视的前提。但严格保持"只展示事实"。

**预估工作量**：中（新增聚合查询 + 简单列表 UI，复用 EventRepository 已有查询）

### 方向 3：上次备份时间静默展示（数据安全）

**为什么**：纯本地 app 数据卸载即失，当前导出全靠用户主动。但产品哲学明确"无提醒推送"——不能用通知催备份。

**是什么**：
- 设置页"导出"入口旁静默显示"上次备份：3 天前 / 从未"
- 不弹窗、不通知、不变红，只是信息在那里
- 用户看到后自行决定是否备份

**不是什么**：
- 不是自动备份（纯本地无后台）
- 不是备份提醒通知（违反"无提醒"哲学）
- 不是备份状态评分

**符合哲学**：轻量存在——信息静静在那，不制造焦虑，不打扰用户。

**预估工作量**：小（记录上次导出时间到 SharedPreferences，设置页展示）

## 不建议的方向（明确排除）

- **云同步 / 账号系统**：违反"纯本地、不联网"核心哲学
- **提醒推送 / 通知**：违反"无提醒推送"明确约束
- **streak 连续记录天数**：滑向打卡应用，制造焦虑，违反"不评判"
- **标签 / 分类**：已于 2026-06-27 移除，用户决策"对纯记录是负担"
- **复盘模板 / 日记引导**：违反"不强迫复盘"
- **社区 / 分享**：违反"无社区"
- **AI 分析 / 洞察建议**：违反"App 反映现实，不评判现实"——AI 建议即评判

## 总结

三个方向中，**方向 1（周视图）**最直接呼应原始诉求且工作量适中，建议优先。**方向 2（时间去向）**价值高但需严格把控"只展示事实"边界。**方向 3（备份时间）**工作量最小，可作为低优先打磨项。

所有方向均严格遵循产品哲学：纯本地、无提醒、不评判、轻量存在。用户决定是否采纳及采纳顺序。
